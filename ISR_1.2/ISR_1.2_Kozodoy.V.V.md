# Поянение к скрипту для автоматизированной установки ПО

## Введение 

В рамках учебной практики была поставлена задача разработать скрипт для автоматизации установки и настройки прикладного программного обеспечения в компьютерных аудиториях. Список необходимого ПО включает более тридцати наименований: браузеры, среды разработки, научные пакеты, языки программирования, утилиты и систему WSL 2 с дистрибутивами Ubuntu.

Список необходимого ПО включает более тридцати наименований: браузеры, среды разработки, научные пакеты, языки программирования, утилиты и систему WSL 2 с дистрибутивами Ubuntu.

## Блок 1. Проверка прав администратора

### Листинг

```batch
@echo off
setlocal enabledelayedexpansion
title Автоматическая установка ПО для аудиторий кафедры ИТ и ЭО

net session >nul 2>&1
if %errorLevel% neq 0 (
    echo [ОШИБКА] Запустите скрипт от имени Администратора!
    pause
    exit /b 1
)
```

### Пояснение

Блок выполняет подготовку среды выполнения и проверку прав доступа. Первая строка `@echo off` отключает вывод команд на экран — в консоли отображаются только результаты их выполнения, что делает вывод скрипта читаемым. Команда `setlocal enabledelayedexpansion` создаёт локальную область видимости переменных и включает режим отложенного раскрытия — это необходимо для корректной работы с переменными внутри блоков `if` и `for` в последующих частях скрипта. Команда `title` устанавливает заголовок окна консоли, чтобы оператор видел, какая именно задача выполняется.

Проверка прав администратора реализована через команду `net session`, которая обращается к службе сервера Windows и успешно выполняется только при наличии административных привилегий. Весь вывод команды перенаправляется в «пустоту» (`>nul 2>&1`), чтобы не засорять консоль. Если код возврата (`%errorLevel%`) отличен от нуля, скрипт выводит сообщение об ошибке, делает паузу для прочтения и завершается с кодом `1`. Это предотвращает частичное выполнение установки с недостаточными правами, что могло бы привести к ошибкам установки пакетов или их установке только для текущего пользователя вместо всех пользователей аудитории.

## Блок 2. Проверка и установка Chocolatey

### Листинг

```batch
echo [1/7] Проверка и установка Chocolatey

where choco >nul 2>&1
if %errorLevel% neq 0 (
    echo Chocolatey не найден. Начинаем установку...
    @"%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe" -NoProfile -InputFormat None -ExecutionPolicy Bypass -Command "iex ((New-Object System.Net.WebClient).DownloadString('https://community.chocolatey.org/install.ps1'))"

    set "PATH=%PATH%;%ALLUSERSPROFILE%\chocolatey\bin"

    where choco >nul 2>&1
    if !errorLevel! neq 0 (
        echo [ОШИБКА] Не удалось установить Chocolatey. Проверьте подключение к интернету.
        pause
        exit /b 2
    )
    echo Chocolatey успешно установлен.
) else (
    echo Chocolatey уже установлен:
    choco --version
)

```

### Пояснение

Блок выполняет установку менеджера пакетов Chocolatey, если он ещё не установлен в системе. Проверка наличия Chocolatey выполняется командой `where choco` — если утилита найдена, код возврата равен 0, и блок переходит в ветку «уже установлен», где выводится текущая версия через `choco --version`. Если Chocolatey отсутствует, скрипт запускает PowerShell с обходом политики выполнения (`-ExecutionPolicy Bypass`) и выполняет официальный установочный скрипт, загружаемый по HTTPS с сайта `community.chocolatey.org`.

После успешной установки переменная `PATH` дополняется путём `%ALLUSERSPROFILE%\chocolatey\bin`, чтобы команда `choco` стала доступна в текущей сессии без перезагрузки. Особенностью этого блока является то, что официальный скрипт-установщик Chocolatey может возвращать ненулевой код завершения при наличии некритичных предупреждений, поэтому проверка успешности установки выполняется не по коду возврата PowerShell, а по факту наличия исполняемого файла `choco.exe` — через повторный вызов `where choco` после обновления переменной `PATH`. Это делает скрипт устойчивым к ложным срабатываниям.

## Блок 3. Установка браузеров, утилит и архиваторов

### Листинг

```batch

echo [2/7] Установка браузеров, утилит и архиваторов

choco install googlechrome firefox yandex-browser 7zip flameshot sumatrapdf far qalculate -y
choco install vscode -y
choco install git github-desktop -y

```

### Пояснение

Все пакеты устанавливаются командой `choco install` с флагом `-y`, который автоматически подтверждает все запросы установщика. Chocolatey сам скачивает установщики с официальных сайтов разработчиков и запускает их в тихом режиме. Несколько пакетов объединены в одну команду для компактности — это стандартная практика Chocolatey, позволяющая устанавливать связанные группы программ одной строкой. VS Code вынесен в отдельную команду, потому что в дальнейшем (в блоке расширений) для него потребуется установить расширения. 

## Блок 4. Установка сред разработки и научного ПО

### Листинг

```batch

echo [3/7] Установка сред разработки и научного ПО

choco install docker-desktop pycharm-community -y
choco install anaconda3 -y
choco install maxima knime gimp zettlr miktex texstudio -y

```

### Пояснение

Так же как и в предидущем блоке каждый пакет устанавливается командой `choco install` с флагом `-y` для автоматического подтверждения. Пакеты сгруппированы в три команды: первая — для сред разработки, вторая — для Anaconda (отдельно, так как она тяжёлая и требует больше времени на установку), третья — для научного ПО.

Особенностью этого блока является то, что часть пакетов (KNIME, MiKTeX, TeXstudio) в репозитории Chocolatey представлена в виде метапакетов, которые ссылаются на `.install`-версии. Chocolatey автоматически разрешает эти зависимости и устанавливает нужную версию. Например, `knime` ссылается на `knime.install`, `miktex` — на `miktex.install`, `texstudio` — на `texstudio.install`. Это стандартный приём менеджера пакетов, позволяющий пользователю писать короткое имя, а системе — самостоятельно выбирать конкретную реализацию.

## Блок 5. Установка языков программирования

### Листинг

```batch

echo [4/7] Установка языков программирования

choco install python rust julia -y
choco install msys2 -y

```

### Пояснение

Python устанавливается через Chocolatey с менеджером пакетов `pip`. Пакет `python` в Chocolatey является метапакетом, который ссылается на `python3`, а тот, в свою очередь, на конкретную версию (например, `python314`). Chocolatey сам разрешает всю цепочку и устанавливает актуальную стабильную версию Python 3.x.

Rust устанавливается вместе с компилятором `rustc` и менеджером пакетов `cargo`. Особенностью пакета `rust` в Chocolatey является то, что он скачивает не установщик, а набор `.tar.gz`-архивов (`rustc`, `cargo`, `rust-std`, `rust-src`, `rust-mingw`), распаковывает их и раскладывает файлы вручную. Это неофициальный способ установки, но он полностью автоматизирован.

Julia устанавливается обычным EXE-установщиком в тихом режиме (`/VERYSILENT`). После установки вызывается `Install-BinFile 'julia' <путь>`, чтобы добавить `julia.exe` в PATH.

MSYS2 устанавливается в `C:\msys64` (стандартный путь). Скрипт установки MSYS2 выполняет несколько шагов: установку, настройку прокси (при необходимости), первый запуск оболочки для инициализации, обновление пакетов и добавление в PATH. Это делает установку MSYS2 более длительной, чем остальных пакетов.

## Блок 6. Установка приложений через winget

### Листинг

```batch

echo [5/7] Установка приложений через winget 

echo Установка Arc Browser...
winget install --id TheBrowserCompany.Arc --silent --accept-source-agreements --accept-package-agreements
if !errorLevel! NEQ 0 (
    echo [!] Arc Browser не установлен. Установите вручную из Microsoft Store.
)

echo.

```

### Пояснение

Блок выполняет установку приложений, отсутствующих в Chocolatey. Основным инструментом здесь выступает `winget` — встроенный менеджер пакетов Microsoft, доступный на Windows 10 (1809+) и Windows 11. В отличие от Chocolatey, `winget` не требует отдельной установки и является частью пакета «App Installer».

Для Arc Browser используется команда `winget install --id TheBrowserCompany.Arc`. Флаг `--id` указывает точный идентификатор пакета, что исключает неоднозначности. Флаги `--silent`, `--accept-source-agreements` и `--accept-package-agreements` обеспечивают полностью неинтерактивную установку: без запросов на принятие лицензий и без графического интерфейса. Проверка `!errorLevel! NEQ 0` позволяет вывести сообщение, если установка не удалась.

## Блок 7. Установка расширений VS Code

### Листинг

```batch

echo [6/7] Установка расширений VS Code

timeout /t 10 /nobreak >nul

code --install-extension ms-python.python
code --install-extension ms-vscode.cpptools
code --install-extension ms-azuretools.vscode-docker
code --install-extension eamodio.gitlens
code --install-extension ritwickdey.LiveServer
code --install-extension ecmel.vscode-html-css
code --install-extension dbaeumer.vscode-eslint
code --install-extension esbenp.prettier-vscode
code --install-extension julialang.language-julia
code --install-extension rust-lang.rust-analyzer
code --install-extension ms-vscode-remote.remote-wsl

```

### Пояснение

Расширения устанавливаются командой `code --install-extension <ID>`, где ID — это идентификатор расширения в формате `<издатель>.<имя>`. Например, `ms-python.python` — официальное расширение Python от Microsoft, `ms-vscode.cpptools` — расширение `C/C++`, `eamodio.gitlens` — популярное расширение для работы с Git.

Для веб-технологий используется набор из четырёх расширений: Live Server (локальный веб-сервер с автоперезагрузкой), HTML CSS Support (автодополнение для HTML/CSS), ESLint (линтер JavaScript) и Prettier (форматтер кода).

Перед установкой расширений добавлена пауза `timeout /t 10 /nobreak >nul` — это необходимо, чтобы VS Code после установки успел зарегистрироваться в системе и команда code стала доступна в текущей сессии. Без паузы установка расширений может упасть с ошибкой «`code` не является внутренней или внешней командой».

## Блок 8. Настройка WSL 2 и ручная установка

### Листинг

```batch

echo [7/7] Настройка WSL 2

if /I "%~1"=="/continue" goto :wsl_install_distros

dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart

if !errorLevel! EQU 3010 set "REBOOT_NEEDED=1"
if !errorLevel! EQU 0 set "REBOOT_NEEDED=0"

if "!REBOOT_NEEDED!"=="1" (
    echo Требуется перезагрузка. После входа скрипт продолжит автоматически.
    schtasks /create /tn "WSL_Install_Continue" /tr "\"%~f0\" /continue" /sc onlogon /rl highest /f >nul

    if !errorLevel! NEQ 0 (
        echo [!] Не удалось создать задачу автопродолжения.
        echo     Запустите скрипт вручную с параметром /continue.
    )

    choice /M "Перезагрузить сейчас"
    if !errorLevel! EQU 1 shutdown /r /t 5
    exit /b
)

goto :wsl_install_distros

:wsl_install_distros
wsl --update
wsl --install -d Ubuntu-22.04
wsl --install -d Ubuntu-24.04
wsl --set-default-version 2

schtasks /query /tn "WSL_Install_Continue" >nul 2>&1
if !errorLevel! EQU 0 schtasks /delete /tn "WSL_Install_Continue" /f >nul 2>&1

echo.
echo Установка завершена.
echo Проверьте WSL: wsl --list --verbose
echo Telemost и Sber Jazz установите вручную.
start "" "https://telemost.yandex.ru"
start "" "https://developers.sber.ru/portal/products/jazz-by-sber"
pause

```

### Пояснение

Блок выполняет настройку подсистемы Windows для Linux (WSL 2) и установку дистрибутивов Ubuntu 22.04 LTS и 24.04 LTS. WSL 2 позволяет запускать полноценное Linux-окружение непосредственно в Windows без использования традиционной виртуальной машины. Особенностью блока является то, что настройка WSL 2 требует перезагрузки после включения компонентов Windows. Пакетный файл .bat не может автоматически продолжить выполнение после перезагрузки, поэтому использован подход с Планировщиком задач Windows.

Логика работы блока:

1. Проверка флага /continue. Если скрипт запущен после перезагрузки задачей Планировщика, он пропускает этап dism.exe и сразу переходит к установке дистрибутивов (метка :wsl_install_distros).

2. Включение компонентов Windows. Через dism.exe включаются два компонента: «Платформа виртуальной машины» (VirtualMachinePlatform) и «Подсистема Windows для Linux» (Microsoft-Windows-Subsystem-Linux). Флаг /norestart предотвращает автоматическую перезагрузку, чтобы скрипт завершился корректно.

3. Проверка кода возврата 3010. Этот код означает «операция успешна, требуется перезагрузка». Если он получен, устанавливается флаг REBOOT_NEEDED=1. Если код 0 — компоненты уже были включены, перезагрузка не нужна, и скрипт сразу переходит к установке дистрибутивов.

4. Регистрация задачи автопродолжения. Если перезагрузка нужна, создаётся задача WSL_Install_Continue в Планировщике задач с триггером onlogon (при входе пользователя) и правами highest (от администратора). Задача запускает тот же самый скрипт с флагом /continue. Это ключевой момент: после перезагрузки и входа пользователя задача автоматически запустит скрипт, который пропустит dism.exe и выполнит установку дистрибутивов.

5. Перезагрузка. Оператору предлагается выбор через choice — перезагрузить сейчас или вручную. При выборе «Да» вызывается shutdown /r /t 

6. Установка дистрибутивов (после перезагрузки). На метке :wsl_install_distros выполняются:

- wsl --update — обновление WSL до актуальной standalone-версии.

- wsl --install -d Ubuntu-22.04 — установка Ubuntu 22.04 LTS.

- wsl --install -d Ubuntu-24.04 — установка Ubuntu 24.04 LTS.

- wsl --set-default-version 2 — установка WSL 2 по умолчанию для будущих дистрибутивов.

7. Удаление задачи. После успешной установки задача WSL_Install_Continue удаляется из Планировщика, чтобы не срабатывать при каждом входе пользователя.

8. Финальное сообщение. Выводятся напоминания проверить WSL и установить Telemost и Sber Jazz вручную. Открываются ссылки на страницы скачивания этих приложений.

Отдельно стоит отметить, что приложения Yandex Telemost и Sber Jazz отсутствуют в публичных репозиториях Chocolatey и winget, а их сайты не предоставляют постоянных прямых ссылок на установщики (URL динамически генерируются при нажатии кнопки «Скачать»). Я пытался реализовать их автоматическую установку через репозиторий на Github, загрузив туда установщики. Скрипт выглядил так:

```batch

echo Установка Sber Jazz...
powershell -NoProfile -ExecutionPolicy Bypass -Command ^
  "(New-Object Net.WebClient).DownloadFile('https://github.com/Happy7atan/dept-installers/releases/download/v1.0/jazz.exe', '%TEMP%\jazz.exe')"

if exist "%TEMP%\jazz.exe" (
    echo Запуск установки Sber Jazz...
    start /wait "" "%TEMP%\jazz.exe" /S
    del "%TEMP%\jazz.exe" 2>nul
    echo Sber Jazz установлен.
) else (
    echo [!] Не удалось скачать jazz.exe. Проверьте ссылку.
)

```

Скрипт скачивает установщики по прямым ссылкам через `WebClient.DownloadFile` и запускает их в тихом режиме с флагом `/S`. После установки временные файлы удаляются. Их установщики были протестированы: Sber Jazz поддерживает флаг `/S` (тихая установка), а Telemost не поддерживает ни один из стандартных флагов (`/S`, `/quiet`, `/VERYSILENT`, `/silent`). Поэтому я отказался от этой идеи и в скрипте предусмотрено только информирование оператора о необходимости ручной установки, а ссылки на страницы скачивания открываются в браузере в финале скрипта.
